## 二、 产品定位

### 2.1 产品愿景

> **让每一个想弹琴的人，都能弹出完整的一首歌。**

轻琴不是要替代钢琴老师，而是解决一个具体问题：**"我想弹这首歌，但五线谱太难了，左手跟不上，弹错了也不知道哪里错。"**

### 2.2 一句话定位

> 轻琴是第一个能将任意五线谱 **AI 自动降维简化**、**实时 MIDI 纠错诊断**、**音游化趣味练习** 三位一体的钢琴学练助手。

### 2.3 核心使用场景

| 场景 | 用户故事 | 对应核心能力 |
|---|---|---|
| **"我想弹这首歌"** | 小王听到一首喜欢的流行歌，找到五线谱，但左手伴奏全是复杂的分解和弦。用轻琴一键生成 Lv1 简化版，右手旋律不变，左手只弹根音，10 分钟就能跟下来 | AI 曲谱降维 |
| **"我弹得对吗"** | 老李跟着简化谱练了几遍，连上 MIDI 键盘，轻琴实时标红弹错的音，练完告诉他"第 8 小节 G7 和弦的 F 音总是弹成 F#，可能是指法问题" | MIDI 智能诊断 |
| **"今天练 15 分钟"** | 小美打开音游模式，音符像游戏一样下落，弹对了 Combo +1，等待模式让她不怕弹错。15 分钟打卡完成，解锁了"连续 7 天"成就 | 音游化练习 |
| **"越练越熟"** | 老李用 Lv1 根音伴奏弹熟了整首歌，切换到 Lv2 柱式和弦继续挑战，最终目标是弹到 Lv3 接近原谱的分解和弦 | 分级渐进体系 |

### 2.4 三大差异化壁垒

| # | 核心能力 | 竞品现状 | 轻琴做法 |
|---|---|---|---|
| 1 | **AI 曲谱降维** | 无产品做到"任意谱自动分级简化" | AI 和声分析 → 左手 3 级简化（根音 → 柱式和弦 → 分解和弦）+ 五线谱/简谱切换 |
| 2 | **深度 AI 诊断** | 仅判断"对/错"，无归因 | MIDI 精准分析 → 诊断报告："哪里错 → 为什么错 → 怎么练" |
| 3 | **音游化练习** | Synthesia 有瀑布流但无学习闭环 | 等待模式 + 分段强化 + 渐进提速 + 打分激励 + 成就系统 |

### 2.5 产品价值公式

```
轻琴的价值 = 降低门槛（曲谱降维）× 提供反馈（AI 诊断）× 增加趣味（音游化）
              ↓                    ↓                   ↓
         解决「不会弹」          解决「不知对错」       解决「不想练」
```

### Phase 0：技术验证期 (POC)

> **周期**：~4 周 | **目标**：验证三大核心能力的技术可行性 | **判定**：Go / No-Go

| # | 验证项 | 具体任务 | 关键技术 | 成功标准 |
|---|---|---|---|---|
| P0-1 | MIDI 接入 | Web MIDI API 连接电钢琴，实时捕获 Note On/Off | Web MIDI API | 延迟 < 20ms，音符捕获 100% |
| P0-2 | 曲谱解析与渲染 | 解析 MusicXML，在浏览器中渲染五线谱和简谱 | OSMD / VexFlow | 能正确显示含和弦的双手谱 |
| P0-3 | 音符对齐算法 | 将用户弹奏 MIDI 与标准谱对齐，识别错音 | DTW 动态时间规整 | 错音识别准确率 > 95% |
| P0-4 | 和声分析原型 | 解析 MIDI 和弦走向，生成简化方案 | 乐理规则引擎 | 3 首测试歌和声分析结果乐理正确 |
| P0-5 | 瀑布流渲染 | Canvas 上实现音符下落动画 + 判定线 | Canvas / PixiJS | 60fps 流畅渲染，MIDI 输入响应 < 30ms |

**Phase 0 产出物**：技术可行性报告 + Demo 原型（能连接 MIDI 键盘 → 显示一首简单曲谱 → 弹奏实时高亮）

---

### Phase 1：Web MVP 内测版

> **周期**：~8 周 | **目标**：最小闭环体验 | **核心命题**："简化谱" 这个需求成不成立？

**用户故事**：用户登录轻琴 → 在 PC Chrome 打开一首歌 → 选难度等级 → 看简化曲谱 → 连接 MIDI 键盘弹奏 → 音游模式打分/跟谱模式纠错 → 练完看报告

**终端边界**：Phase 1 的实时练习主场景只定义为 **PC Chrome + Web MIDI**。iPad Web 端可做浏览和预览，但不承担正式 MIDI 练习。

#### 功能清单

| # | 功能 | 优先级 | 说明 |
|---|---|---|---|
| P1-1 | 内置曲库（5-10 首） | P0 | **人工编排**多难度版本（不依赖 AI 自动简化），先验证需求 |
| P1-2 | 曲谱显示引擎 | P0 | 五线谱 / 简谱双模式 + 左手 3 级难度切换 |
| P1-3 | MIDI 实时连接 | P0 | PC Chrome 上连接 USB/蓝牙 MIDI 键盘 + 弹奏音符实时高亮 |
| P1-4 | 瀑布流音游模式 | P0 | 等待模式（弹对才走）+ 自由模式（原速下落）|
| P1-5 | 基础评分报告 | P1 | 单次练习结束：准确率、节奏偏差统计 |
| P1-6 | 曲谱跟随播放 | P1 | 自动滚谱 + 当前小节高亮 + 节拍器 |
| P1-7 | 用户账号系统 | P1 | 测试期账号密码登录 + 练习记录按用户存储，后续扩展手机号登录 |

#### 明确不做
- AI 自动曲谱简化（用人工编排验证核心假设）
- 深度 AI 诊断报告（Phase 2）
- 社区 / 曲库上传
- 声学钢琴听音
- iPad Safari / PWA 的 Web MIDI 练习

#### Web MVP 核心验证指标

| 指标 | 含义 | 目标值 |
|---|---|---|
| **完曲率** | 用户是否因为左手简化而弹完整首歌 | > 60% |
| **模式偏好** | 等待模式 vs 自由模式的选择比例 | 观测 |
| **次日留存** | 用户第二天还会回来练吗 | > 30% |
| **难度升级率** | 用 Lv1 弹熟后主动切到 Lv2 的比例 | > 40% |

**Phase 1 → Phase 2 的决策标准**：完曲率 > 60% 且用户反馈证实"左手简化"是核心吸引力

### Phase 1.5：iPad 原生练琴版

> **周期**：~4-6 周 | **目标**：在保留 Web 已验证核心能力的前提下，把练琴主场景落到标准 iPad App

| # | 功能 | 说明 |
|---|---|---|
| P1.5-1 | **标准 iPad App 外壳** | 使用原生 App 承载练琴页面，解决 iPad 浏览器不支持 Web MIDI 的问题 |
| P1.5-2 | **原生 MIDI 接入** | 通过 iPad 原生 MIDI 能力接入电钢琴，复用既有判定与练习逻辑 |
| P1.5-3 | **账号与练习记录打通** | 与 Web 版共用账号体系和练习记录 |
| P1.5-4 | **内部测试分发** | 先满足开发者本人设备安装与测试，后续如需外部测试再接入正式分发方案 |

**Phase 1.5 原则**：不是重做一套产品，而是在复用 Web 版核心引擎和谱面数据的前提下，补齐 iPad 的 MIDI 能力。

---

### Phase 2：AI 能力构建版

> **周期**：~12 周 | **目标**：将"人工编排"替换为"AI 自动生成"，建立技术壁垒

| # | 功能 | 说明 |
|---|---|---|
| P2-1 | **AI 自动曲谱简化引擎** | 用户上传任意 MusicXML/MIDI → AI 分析和声 → 自动生成左手 3 级简化 |
| P2-2 | **AI 智能指法推荐** | 基于简化后的曲谱，自动标注推荐指法 |
| P2-3 | **深度练习诊断报告** | 错音统计（精确到小节+音名）、节奏偏差可视化、AI 文字建议 |
| P2-4 | **分段强化练习** | AI 识别错误率最高的小节 → 自动生成专项练习片段 |
| P2-5 | **变速渐进模式** | 50% 速度起步，弹对 N 次自动提速，直至原速 |
| P2-6 | **曲库扩展** | 基于 AI 简化引擎，批量生成更多曲目的多难度版本 |

**Phase 2 的关键里程碑**：AI 简化引擎上线后，新曲目上架速度从"人工编排 1 首/周"提升至"AI 生成 50 首/天"

### Phase 3：生态与增长版

> **周期**：持续迭代 | **目标**：构建内容生态和用户粘性，驱动增长飞轮

| # | 功能 | 说明 |
|---|---|---|
| P3-1 | **在线曲库市场** | 分难度等级的精编流行歌、古典入门曲目，支持搜索和分类 |
| P3-2 | **用户 UGC 曲谱** | 用户上传曲谱 → AI 自动生成简化版 → 社区分享 |
| P3-3 | **AI 虚拟陪练** | 大模型驱动的语音/文字互动（鼓励、建议、答疑）|
| P3-4 | **练琴激励体系** | 练琴日历 + 连续打卡 + 成就徽章 + 排行榜 |
| P3-5 | **PDF 曲谱导入** | OCR 识别 PDF 曲谱 → 转 MusicXML → AI 简化 |
| P3-6 | **多端练琴体验优化** | iPad 分屏、离线缓存、外接显示器/琴架场景优化 |

**增长飞轮**：更多曲目 → 更多用户 → 更多 UGC 上传 → AI 简化 → 更多曲目

## 五、 平台策略与技术栈

### 5.1 平台优先级

| 优先级 | 平台 | 说明 |
|---|---|---|
| **P0** | Web App（PC Chrome） | 先跑通核心体验，实时 MIDI 练习主场景锁定 PC Chrome |
| **P1** | 标准 iPad App | Web 跑通后直接做原生 iPad App，解决平板 MIDI 连接问题 |
| **P2** | 桌面客户端 | 如需更低 MIDI 延迟，可考虑 Electron 或 Tauri 封装 |
| 不做 | iPad Safari Web MIDI / 手机 App | iPad 浏览器不作为正式 MIDI 练习终端；手机屏幕太小不适合曲谱显示和练琴场景 |

### 5.2 技术栈初步选型

| 层 | 选型 | 理由 |
|---|---|---|
| Web 主应用 | **Next.js** | 既能做前端页面，也能承载登录、接口和练习记录存储 |
| 曲谱渲染 | OpenSheetMusicDisplay / VexFlow | 开源、MusicXML 支持好 |
| MIDI 接入 | Web MIDI API | 浏览器原生支持，无需额外驱动 |
| 音游渲染 | Canvas / WebGL (PixiJS) | 高性能 2D 渲染，适合瀑布流 |
| 和声分析 | tonal.js + 自研规则引擎 → 后期 ML | 先规则引擎验证，再上 ML |
| 账号与接口 | Next.js Route Handlers / Server Actions | MVP 已包含登录和练习记录，不能再按纯静态站点设计 |
| 后端扩展 | Python (FastAPI) | AI 模型推理阶段再引入 |
| AI 诊断 | LLM (大模型) + 结构化 MIDI 分析数据 | 结合规则分析和大模型生成自然语言建议 |

## 六、 风险与待验证假设

| # | 假设 | 风险等级 | 验证方式 |
|---|---|---|---|
| 1 | 成人初学者的核心卡点是"左手太难" | 🔴 高 | MVP 内测用户访谈 |
| 2 | AI 自动简化的和弦听起来不会太难听 | 🔴 高 | 乐理专家审核 + 用户盲测 |
| 3 | 用户愿意为"AI 简化曲谱"付费 | 🟡 中 | 定价 A/B 测试 |
| 4 | Web MIDI API 延迟满足实时反馈需求 | 🟢 低 | POC 测试（通常 < 10ms） |
| 5 | 音游模式能显著提升练琴坚持率 | 🟡 中 | MVP 留存数据 |
| 6 | 简谱显示对中国用户有独特吸引力 | 🟡 中 | 国内用户测试 |
