## 一、 MVP 目标

### 1.1 核心命题

> **"左手简化曲谱" 这个需求到底成不成立？**

MVP 不是要做一个完整产品，而是用最短路径验证一个假设：**如果我们把五线谱的左手伴奏大幅简化，成人初学者是否就愿意弹完一整首歌、并且第二天还会回来继续练？**

### 1.2 成功标准

| 指标 | 目标值 | 含义 |
|---|---|---|
| **完曲率** | > 60% | 用户选了一首歌后，弹完整首的比例 |
| **次日留存** | > 30% | 第二天还回来练的比例 |
| **难度升级率** | > 40% | Lv1 弹熟后主动升到 Lv2 的比例 |
| **NPS 评分** | > 30 | 内测用户推荐意愿 |

## 二、 产品范围

### 2.1 用户故事主线

```
用户登录轻琴 → 在 PC Chrome 选一首歌 → 选难度(Lv1/Lv2/Lv3) → 选谱面(五线谱/简谱)
    → 连接 MIDI 键盘 → 选练习模式(音游/跟谱) → 弹奏 → 看评分报告
```

### 2.2 功能清单

| 编号 | 功能模块 | 优先级 | 描述 |
|---|---|---|---|
| **F0** | 测试登录 | P0 | 账号密码登录，测试期以预置账号或白名单账号为主 |
| **F1** | 首页 / 曲目选择 | P0 | 内置 5-10 首曲目的列表，显示曲名、难度标签、时长 |
| **F2** | 曲谱显示引擎 | P0 | 五线谱 / 简谱双模式渲染 + 左手 3 级难度实时切换 |
| **F3** | MIDI 键盘连接 | P0 | 在 PC Chrome 中通过 Web MIDI API 检测和连接，显示连接状态 |
| **F4** | 音游模式（瀑布流） | P0 | 下落式音符 + 等待模式 + 自由模式 + 基础打分 |
| **F5** | 跟谱练习模式 | P1 | 五线谱/简谱自动滚动 + 实时音符高亮（弹对绿/弹错红）|
| **F6** | 练习评分报告 | P1 | 单次练习结束后：准确率、节奏评价、错音小节概览 |
| **F7** | 设置 | P2 | 音量、节拍器开关、瀑布流速度调节 |
| **F8** | 账号与练习记录 | P1 | 练习记录按登录用户存储，为后续手机号登录预留扩展空间 |

### 2.3 明确不做

- ❌ AI 自动曲谱简化（人工编排验证需求）
- ❌ 深度 AI 诊断报告（Phase 2）
- ❌ 曲库上传 / 社区分享
- ❌ 声学钢琴听音识别
- ❌ iPad Safari / PWA 的 Web MIDI 练习
- ❌ 手机号登录
- ❌ 用户注册/付费系统

## 三、 页面与交互设计

### 3.1 页面结构

```
┌─────────────────────────────────────────────────────┐
│  轻琴 PianoEase                                      │
├─────────────────────────────────────────────────────┤
│                                                      │
│  P0. 登录页                                            │
│     └── P1. 首页（曲目列表）                            │
│          ├── P2. 曲目详情 / 练习准备页                  │
│          │     ├── P3a. 音游模式（瀑布流）               │
│          │     └── P3b. 跟谱练习模式                    │
│          │           └── P4. 练习报告页                 │
│          └── P5. 设置页                                │
│                                                      │
└─────────────────────────────────────────────────────┘
```

### 3.2 P0 — 登录页

**布局**：居中登录卡片，输入项尽量精简

**输入项**：
- 用户名 / 邮箱
- 密码

**交互要求**：
- 测试账号密码登录成功后进入首页
- 错误提示简洁明确，不引入注册和找回密码流程
- 登录态持久化，刷新后仍保持会话

### 3.3 P1 — 首页（曲目列表）

**布局**：卡片网格，每张卡片代表一首曲目

**每张卡片信息**：
- 曲名（中文）+ 英文/原名
- 难度标签（入门 / 进阶 / 挑战）
- BPM + 时长
- 缩略预览（前4小节简谱缩略图）

**交互**：
- 点击卡片 → 进入 P2 练习准备页
- 顶部 MIDI 状态指示灯（🟢已连接 / 🔴未连接，点击可配置）

### 3.4 P2 — 练习准备页

**核心选择项**：

| 选项 | 可选值 | 默认值 |
|---|---|---|
| 左手难度 | Lv1 根音 / Lv2 柱式和弦 / Lv3 分解和弦 | Lv1 |
| 谱面模式 | 五线谱 / 简谱 | 简谱 |
| 练习模式 | 🎮 音游模式 / 📖 跟谱模式 | 音游模式 |
| 速度 | 50% / 75% / 100% | 100% |

**底部**：大按钮 **[开始练习]**

**预览区**：显示当前选择的难度和谱面下的前 4 小节效果

### 3.5 P3a — 音游模式（瀑布流）

**布局**：

```
┌──────────────────────────────────────┐
│  曲名        00:32 / 02:15    ⏸ ✕   │  ← 顶栏：进度、暂停、退出
├──────────────────────────────────────┤
│                                      │
│    ██                                │
│       ██  ██                         │  ← 音符块下落区
│          ██     ██                   │    左手蓝色 / 右手绿色
│    ██        ██    ██                │
│       ██  ██    ██                   │
│                                      │
│══════════════════════════════════════│  ← 判定线
│  ┃  ┃  ┃  ┃  ┃  ┃  ┃  ┃  ┃  ┃  ┃  │  ← 虚拟琴键（显示用）
│  C  D  E  F  G  A  B  C' D' E' F'  │
├──────────────────────────────────────┤
│  Combo: 12    Score: 860    ⭐⭐⭐    │  ← 底栏：实时打分
└──────────────────────────────────────┘
```

**两种子模式**：

| 子模式 | 行为 | 适合 |
|---|---|---|
| **等待模式** | 音符到达判定线后暂停，用户弹对正确音符后继续 | 初学者拆谱 |
| **自由模式** | 音符按设定速度持续下落，提供 Perfect/Good/Miss 判定 | 有一定基础后挑战 |

**打分逻辑**：
- **Perfect**：在判定窗口 ±50ms 内弹对 → +100 分
- **Good**：在判定窗口 ±150ms 内弹对 → +50 分
- **Miss**：超出窗口或弹错 → 0 分，Combo 断裂
- Combo 连击倍率：10连 ×1.5，30连 ×2.0，50连 ×3.0

### 3.6 P3b — 跟谱练习模式

**布局**：

```
┌──────────────────────────────────────┐
│  曲名       Lv1 根音    简谱   ⏸ ✕  │
├──────────────────────────────────────┤
│                                      │
│  右手：3'  1'6 631'6 | 4  1'6 641'6 │  ← 曲谱滚动区
│  左手：6,,          | 4,,           │    当前小节高亮
│                                      │
│  右手：3'  75 #5375  | 3' 1'6 631'6 │
│  左手：3,,           | 6,,          │
│                                      │
├──────────────────────────────────────┤
│ 🎹 实时反馈：                         │
│  ✅ C4  ✅ E4  ❌ F#4(应为F4)  ✅ G4  │  ← 弹奏实时反馈
├──────────────────────────────────────┤
│  节拍器：♩= 74    ▶ 播放 / ⏹ 停止    │
└──────────────────────────────────────┘
```

**核心交互**：
- 曲谱自动跟随当前弹奏位置滚动
- 弹对的音符：绿色高亮
- 弹错的音符：红色高亮 + 显示"应为 XX"
- 漏弹的音符：灰色标记

### 3.7 P4 — 练习报告页

**练习结束后自动弹出**：

| 区域 | 内容 |
|---|---|
| 总分/星级 | ⭐⭐⭐ 860分 |
| 准确率 | 右手 92% / 左手 78% |
| 节奏评价 | 整体偏快 3%，第 8 小节附点节奏不稳 |
| 错音热力图 | 按小节显示哪些地方弹错最多（色块深浅） |
| 操作按钮 | [再练一次] [换难度] [回首页] |

## 四、 内置曲库（人工编排）

### 4.1 选曲原则

- 知名度高（用户一听就知道的歌）
- 和弦进行简洁（优先 4-6 个和弦以内）
- 节奏不太复杂（避免大量切分、变拍号）
- 覆盖不同情绪（抒情/欢快/激昂）

### 4.2 候选曲目列表

| # | 曲名 | 调号 | BPM | 和弦数 | 难度 | 选入理由 |
|---|---|---|---|---|---|---|
| 1 | 友情岁月 | bE | 74 | 6 | 入门 | 用户已提供示范，验证简化规则 |

> 其余曲目待后续基于此标准补充。

**每首曲目需产出**：
- 原始作者源文件：右手旋律 + 左手原谱 MusicXML
- 左手 Lv1 (根音长音) MusicXML
- 左手 Lv2 (柱式和弦) MusicXML
- 左手 Lv3 (分解和弦) MusicXML
- 统一运行时 `chart JSON`（供瀑布流、判定、报告、简谱共用）
- 对应简谱数据和预览缩略数据

## 五、 技术架构

### 5.1 整体架构

```
┌─────────────┐    USB/BLE     ┌──────────────────────────────┐
│  电钢琴      │ ───MIDI────→  │   PC 浏览器 (Chrome)          │
│  (Yamaha等)  │               │                              │
└─────────────┘               │  ┌─ Web MIDI API ──────────┐ │
                              │  │  MIDI 输入管理器         │ │
                              │  └────────┬────────────────┘ │
                              │           │                   │
                              │  ┌────────▼────────────────┐ │
                              │  │    练琴核心引擎           │ │
                              │  │  · chart 数据读取        │ │
                              │  │  · 音符对齐与判定        │ │
                              │  │  · 评分与报告聚合        │ │
                              │  └────────┬────────────────┘ │
                              └───────────│───────────────────┘
                                          │ HTTPS
                              ┌───────────▼───────────────────┐
                              │       Next.js 应用             │
                              │  · 登录 / Session / 鉴权      │
                              │  · 曲库与练习页面             │
                              │  · 练习记录接口与存储         │
                              │  · 静态 MusicXML / chart 资源 │
                              └──────────────────────────────┘
```

### 5.2 技术选型

| 模块 | 选型 | 理由 |
|---|---|---|
| 框架 | **Next.js (App Router)** | 练习页是前端重交互，但 MVP 已包含登录和数据存储，需要一体化工程 |
| 登录 | **账号密码登录 + Cookie Session** | 测试期实现最短路径，后续可扩展到手机号登录 |
| MIDI | **Web MIDI API** (原生) + **webmidi.js** (封装库) | 简化 MIDI 消息处理 |
| 五线谱 | **OSMD** (OpenSheetMusicDisplay) | 最成熟的开源 MusicXML 渲染库 |
| 简谱 | **自研 React 组件** | 无成熟开源库，参考 xml2jianpu 逻辑自建 |
| 瀑布流 | **Canvas 2D** 参考 Midiano | 性能好，开源可参考 |
| 音频 | **Tone.js** | 预听音效、节拍器、倒计时音效 |
| 状态管理 | **Zustand** | 轻量，适合中小项目 |
| 数据存储 | **数据库 + 静态曲谱资源** | 登录和练习记录需要服务端存储；曲谱资源仍可按静态文件管理 |

### 5.3 MVP 后端策略

MVP 阶段**需要轻量后端能力**：
- 登录、Session、用户信息和练习记录由 Next.js 服务端处理
- 曲谱资源仍以静态 `MusicXML/chart JSON` 文件为主，随应用部署
- 练习报告结果按用户存储，便于后续跨设备和 iPad App 共用

### 5.4 统一谱面数据原则

- `MusicXML` 是人工编排和五线谱渲染的源文件
- `chart JSON` 是运行时唯一标准格式
- 瀑布流、判定、跟谱高亮、报告统计都基于 `chart JSON`
- 简谱视图可以有独立渲染结构，但时间轴必须映射到同一份 `chart` 事件
